# Python 技术栈规则

适用范围：组件根目录下存在 `pyproject.toml` / `requirements.txt` / `Pipfile`。本文件提供 Python 专属的**代码理解切入点**。通用概念（逻辑模块定义、判定信号、粒度）见 SKILL.md。

## 核心原则

**Python 包/模块文件是覆盖代码的粒度，不是模块粒度。** 一个逻辑模块可覆盖多个包；多个内聚的包也可归为一个逻辑模块。不要"每包/每文件 = 一模块"。

## 代码理解切入点

| 标志 | 用法 |
| --- | --- |
| `__init__.py` 的导出 | 包的对外契约 |
| 继承同一基类 / 实现同一 Protocol(ABC) 的多个类 | 归为一个逻辑模块（如多个 provider 都继承同一基类 → "provider 适配"一个模块），不各列 |
| `@dataclass` / Pydantic Model | 核心数据载体，跨包共用的核心 model 常标志一个模块 |
| 调用链（import 关系） | 内聚性证据 |

## Python 特定的归类模式

- **一个 Protocol/ABC + 多实现 = 一个模块**：实现同一协议的多个包归为一个逻辑模块，各实现作为覆盖代码。
- **跨包内聚 = 合并**：分散在多包但共同实现一个能力的代码合并（如"鉴权"跨多个 auth 相关包）。
- 同构实现不各列（反例见 SKILL.md）。

## 覆盖代码标注

用包/模块路径标注（相对组件根），例：`app/auth/`、`app/providers/*/`（多个 provider 通配）。

## 排除项

虚拟环境（`.venv/`/`venv/`）、构建产物（`dist/`/`build/`/`*.egg-info/`）、测试固件。
