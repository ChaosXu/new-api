# 产出物：组件运行时关系（{组件名}/relation/*.md）

## 是什么

从**某一个组件的视角**，描述它的**运行时**关系（运行期间发生的交互），按**方向 × 内外**分类，每种关系单独一个文件，放在该组件的 `relation/` 子目录下。

> 编译时关系（产物嵌入产物，如 `go:embed` / `extraResources`）不在这里，见 `references/build.md`。

## 分类

| 分类 | 方向 | 范围 | 文件 | 判定 |
| --- | --- | --- | --- | --- |
| 入站·内部 | 对方→本组件 | 其他组件 | `relation/inbound-internal.md` | 运行时其他组件主动调用/连入本组件（如父进程 spawn、其他组件的 HTTP 调用） |
| 入站·外部 | 对方→本组件 | 外部角色/系统 | `relation/inbound-external.md` | 运行时外部角色（人）或外部系统主动连入本组件。**外部角色（人）归此类**（如用户访问、API 调用方请求、webhook 回调） |
| 出站·内部 | 本组件→对方 | 其他组件 | `relation/outbound-internal.md` | 运行时本组件主动调用/连出其他组件（如托管其他组件的静态资源、调用其他组件接口） |
| 出站·外部 | 本组件→对方 | 外部系统 | `relation/outbound-external.md` | 运行时本组件主动调用外部系统（如转发上游 API、发起支付、发邮件） |
| 基础设施 | 双向 | 设施 | `relation/infrastructure.md` | 本组件直接连接的支撑设施（数据库、缓存、消息队列、对象存储 等） |

规则：
- **只分析运行时**关系。开发态关系按其运行时方向归入对应分类，在"说明"里注明"开发态"。
- 某分类若该组件**无此类关系，不建空文件**。
- 每个文件只列本组件的**直接**关系；经其他组件中转的不列。

## 数据源

| 分类 | 证据来源 |
| --- | --- |
| 入站·内部 | 其他组件运行入口中调用本组件的代码：子进程 spawn、HTTP/RPC 客户端调用指向本组件 |
| 入站·外部 | 本组件的对外接口与鉴权：路由分组 + 认证中间件（外部角色）、webhook 回调端点（外部系统） |
| 出站·内部 | 本组件调用其他组件的代码：托管静态资源（同源 serve）、HTTP/RPC 客户端指向其他组件 |
| 出站·外部 | 本组件的出站调用：渠道/适配器目录、支付/OAuth/邮件 SDK 调用、提供商枚举 |
| 基础设施 | 本组件直接连接设施：DB 驱动 manifest、ORM dialect、Redis/消息队列客户端与连接配置 |

> **易遗漏场景——前后端双向交互**：前端组件（被后端托管静态资源）与后端组件之间通常有**两条方向相反的独立关系**：后端向前端下发静态资源（后端→前端，前端的 inbound-internal）+ 前端在浏览器运行后调用后端 API（前端→后端，前端的 outbound-internal）。两者性质不同，**不能只写一条**。凡是组件间存在"托管/加载 + 调用"的成对交互，务必双向都检查。

## 怎么做

1. **逐分类显式判断**：对 5 个分类逐一回答"本组件是否有此类关系"。**每个分类都必须显式判断**——有则进入下一步；无则在内部推理中明确"为什么无"（不产出，但必须想过），避免某分类因思维盲区被整体跳过。
2. **双向交叉校验**：每当本组件与另一组件存在某方向关系，**必须显式检查是否存在反向关系**（即使性质不同）。常见情形：
   - 前后端：A 托管 B 静态资源（A→B）vs B 调用 A 的 API（B→A）——两条独立关系。
   - 父子进程：A spawn B（A→B）vs B 向 A 上报/响应（B→A，若存在）。
   - 反向不必都有，但必须**显式确认**有无，不可默认无。
3. 对判断为"有"的分类，读取对应模板（`assets/<分类名>.md`），填入：
   - 一张 Mermaid 关系图：本组件居中，对方按类型用不同节点（内部组件方框 `[]`、外部角色圆角 `()`、外部系统/基础设施圆柱 `[()]`），边标注方式。
   - 一张表：对方 | 方式 | 说明。（基础设施表可加"方向"列，因为常为双向）
4. 命名用 `components.md` 中的实际组件名、`L1/context.md` 中的实际外部实体名，不臆造。
5. 删除模板中的 HTML 注释后交付。
6. 无关系的分类**不建文件**（但第 1 步必须显式排除过）。

## 模板

- `assets/inbound-internal.md`
- `assets/inbound-external.md`
- `assets/outbound-internal.md`
- `assets/outbound-external.md`
- `assets/infrastructure.md`

## 写入路径

`specs/03-ARCH/L2/{组件名}/relation/{分类名}.md`（按需创建 `relation/` 子目录；无关系的分类不建）。
