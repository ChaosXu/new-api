# 产出物：组件关系（{组件名}/relation.md）

## 是什么

从**某一个组件的视角**，描述它的全部直接关系，分三部分：

1. **与其他组件的关系**（组件间）：本组件与同系统内其他组件的关系，是 L2 容器协作视图。
2. **与外部的关系**（组件↔外部）：本组件直接对接的外部角色（人）与上游服务（业务对话方，如上游 API、支付、OAuth）。这是 L1 系统上下文（系统↔外部）在本组件上的落地——L1 把系统当黑盒，而本部分指出每条外部交互实际由哪个组件承载。
3. **依赖的基础设施**（组件↔设施）：承载本组件运行的支撑设施（数据库、缓存、消息队列 等）。它们是"系统如何落地"的内部决策，不属对外的业务关系，与上游服务性质不同，故单列一节。

三部分都**只写本组件的直接关系**：组件间部分不写别人之间的关系（归各自组件）；外部与设施部分只写本组件直接对接的实体（不经其他组件中转的）。

每个组件各产出一份，放在该组件自己的目录下。

## 数据源

| 要识别 | 证据来源 |
| --- | --- |
| 组件间·编译时 | 构建配置：`go:embed`、打包工具的 `bundle`/`extraResources`、`workspaces`、`replace`；产物嵌入产物的情况 |
| 组件间·运行时 | 本组件 overview 的"边界与依赖"字段；运行入口：子进程 spawn、反向代理配置、同源托管；HTTP/RPC/gRPC 出站调用 |
| 组件间·开发态 | dev server 代理配置（如 Rsbuild/webpack 的 `proxy`）、`NODE_ENV=development` 分支、开发用占位文件 |
| 组件↔外部·角色 | 本组件面向的用户类型与权限分层：认证中间件、路由访问控制、前端路由守卫（若该组件承载用户界面） |
| 组件↔外部·上游服务 | 本组件直接调用的业务对话方：出站调用、渠道/适配器目录、提供商枚举、webhook 回调配置 |
| 组件↔设施 | 本组件直接连接的支撑设施：数据库驱动 manifest、连接配置、ORM dialect、缓存/消息中间件客户端与连接配置、对象存储 |

> 外部角色与上游服务的完整清单参见 L1（`specs/03-ARCH/L1/context.md`）。本部分只标注其中由**本组件直接承载**的那些。

## 怎么做

1. 读取模板 `assets/relation.md`。
2. 填**与其他组件的关系**（模板"与其他组件的关系"区）：
   - 画本组件为中心的关系图（Mermaid）：本组件居中，周围是与本组件有直接关系的组件（方框 `[]`）；边标注关系类型与方向，时机区分用边注（开发态可用虚线 `-.->`）。**不画**与本组件无直接关系的组件对。
   - 填交互表：对方组件 | 时机（编译时 / 运行时 / 开发态）| 方向 | 方式 | 说明。
3. 填**与外部的关系**（模板"与外部的关系"区）：
   - 画本组件与外部的关系图（Mermaid，可与组件间图合并为一张，也可分两张）：本组件居中，外部角色用圆角 `()`，上游服务用圆柱 `[()]` 或方框；边标注交互方式（如"HTTP API""转发""回调"）。
   - 填外部交互表，分两类：
     - 外部角色（对方角色 | 方向 | 方式 | 说明）
     - 上游服务（对方系统 | 方向 | 方式 | 说明）——业务对话方，如上游 API、支付网关、OAuth 提供商、邮件/通知网关。
   - 只列本组件直接对接的外部实体；若某外部实体经其他组件中转（非本组件直接对接），不在此列。
4. 填**依赖的基础设施**（模板"依赖的基础设施"区）：
   - 画本组件与基础设施的关系图（Mermaid）：本组件居中，设施用圆柱 `[()]`；边标注交互方式（如"读写""缓存""限流"）。
   - 填基础设施表：设施 | 方向 | 方式 | 说明。
   - 基础设施是承载本组件运行的支撑设施（数据库、缓存、消息队列、对象存储 等），与上游服务性质不同，故单列。若本组件不直接连接任何基础设施，本节注明为空。
5. 命名用 `components.md` 中的实际组件名、`L1/context.md` 中的实际外部实体名，不臆造。
6. 删除模板中的 HTML 注释后交付。
