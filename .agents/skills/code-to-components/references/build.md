# 产出物：组件编译时关系（{组件名}/build.md）

## 是什么

从**某一个组件的视角**，描述它的**编译时**关系——即构建期间，其他组件的产物如何被嵌入本组件制品，或本组件的产物如何被嵌入其他组件制品。

> 运行时关系（运行期间的交互）不在这里，见 `references/relation.md`。

## 判定

编译时关系的标志是**产物嵌入产物**：一个组件的构建产物（静态站点、二进制、资源包 等）在另一个组件的构建过程中被嵌入其制品，产出单体制品。典型机制：

| 机制 | 证据 |
| --- | --- |
| `go:embed` | Go 源码中 `//go:embed <path>` 指令，把其他组件的产物目录嵌入本组件二进制 |
| 打包工具 bundle / extraResources | 打包配置（如 Electron `extraResources`、webpack `CopyPlugin`）把其他组件产物打入本组件包 |
| workspaces / monorepo 构建链 | 构建脚本依赖另一组件的产物路径（先构建 A，再构建 B 时引用 A 的 dist） |
| `replace` / 本地 module | Go `replace => ./xxx` 指向仓库内另一组件源码（编译期链接，非运行时调用） |

注意区分：
- **编译时嵌入**（产物嵌入产物，本文件）vs **运行时调用**（进程间通信，归 `relation/`）。
- 即使有 `replace` 指向内部 module，若该 module 是纯库被 import，属编译期链接，归本文件。

## 怎么做

1. 读取模板 `assets/build.md`。
2. 扫描构建配置（`Dockerfile`、`go:embed` 指令、打包工具配置、`workspaces`、`replace`、构建脚本）。
3. 识别本组件制品与其他组件产物的嵌入关系，分两个方向：
   - **本组件嵌入他人**：本组件构建时把其他组件产物嵌入自己制品（如 new-api 用 `go:embed` 嵌入 web/dist）。
   - **他人嵌入本组件**：本组件的产物被其他组件构建时嵌入（如 web/dist 被 new-api 嵌入）。
4. 填入：
   - 一张 Mermaid 图：本组件居中，相关组件用方框 `[]`，边标注嵌入机制与方向。
   - 一张表：对方组件 | 方向（本组件嵌入对方/对方嵌入本组件）| 机制 | 说明。
5. 命名用 `components.md` 中的实际组件名，不臆造。
6. 删除模板中的 HTML 注释后交付。
7. 若本组件无任何编译时嵌入关系（既不嵌入他人，也不被嵌入），**不建此文件**。

`assets/build.md`
