# 业务流程（BPMN 2.0）

> 基于 new-api 代码归纳的端到端业务流程，以 Mermaid flowchart 表达标准化 BPMN 2.0 业务模型。每个流程包含参与者、流程图、流程描述，主路径与异常路径均闭环。

共 **5 个业务分组、19 个业务流程**。流程源于代码实现（controller/service/model/middleware/router），与 [02-用户故事](../02-用户故事/) 的功能一一对应但视角不同：用户故事聚焦"角色 + 价值"，业务流程聚焦"活动 + 流转 + 分支 + 异常"。

## 跨流程关键概念

- **三层鉴权模型**：粗粒度 `AdminAuth`/`RootAuth`（角色数值）→ 细粒度 `RequirePermission`（Casbin RBAC）→ 业务内 `canManageTargetRole`/`channelHasSensitiveChanges`/`requirePaymentCompliance`/`SecureVerificationRequired`。
- **支付合规前置网关**：`IsPaymentComplianceConfirmed` 是所有资金流功能（兑换码、充值、订阅、邀请奖励）的第一道网关，需超管确认。
- **计费安全不变量**：quota 转换走 `common/quota_math.go` 饱和到 int32 防溢出，永不产生负扣费，饱和事件审计到日志。
- **会话安全补偿**：改密码/2FA/Passkey/删除均触发 `IncrementUserAuthVersion` + `RevokeAllUserSessions`。
- **幂等设计**：支付回调（状态机 + 订单锁 + CAS）、订阅预扣（requestId 唯一索引）、异步任务结算（CAS UpdateWithStatus）。
