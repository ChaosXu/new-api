# 首次部署初始化

## 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 访客 | 用户角色 | 在站点首次部署时提交 Root 账号信息，接管站点 |
| 系统启动器 | 系统 | 进程启动时检测 `setups` 表与是否存在 Root 用户，决定是否处于初始化态 |
| 关系数据库 | 外部系统 | 持久化 `setups` 记录、Root 用户、系统选项（Option） |

## 流程图

```mermaid
flowchart TD
    START([Start - 进程启动]) --> T1[系统启动器检查 setups 表与 Root 用户是否存在]
    T1 --> G1{已存在 Setup 记录或 Root 用户?}
    G1 -- 是（已初始化） --> G2[标记 Setup=true，站点进入正常态]
    G2 --> END_RUN([End - 正常运行])
    G1 -- 否（首次部署） --> G3[标记 Setup=false，开放初始化入口]
    G3 --> WAIT([等待访客发起初始化])

    WAIT --> T2[访客 GET /api/setup 读取初始化状态]
    T2 --> T3[访客提交 POST /api/setup：用户名/密码/确认密码/自用模式/演示模式]
    T3 --> G4{constant.Setup == true ?}
    G4 -- 是（已被他人初始化） --> END_FAIL1([End - Cancel：拒绝重复初始化])
    G4 -- 否 --> G5{rootExists == false 且字段校验通过?}
    G5 -- 用户名长度>12/密码不一致/密码长度<8 --> END_FAIL2([End - Cancel：参数校验失败])
    G5 -- 通过 --> T4[创建 Root 用户 Role=100/Status=Enabled/Quota=100000000]
    T4 --> T5[写入系统选项 SelfUseModeEnabled / DemoSiteEnabled]
    T5 --> T6[创建 setups 记录，标记 constant.Setup=true]
    T6 --> END_OK([End - Success：站点初始化完成，访客成为 Root])
```

## 流程描述

本流程是站点从"空白部署"到"可被管理"的引导流程。进程启动时由系统启动器检查 `setups` 表与 Root 用户是否已存在（`model/main.go:80` `CheckSetup`）：若存在则标记 `constant.Setup=true` 进入正常运行；否则保持 `Setup=false`，开放 `GET/POST /api/setup` 供访客完成接管。

访客提交初始化请求后，系统先做"是否已被初始化"网关判定（`controller/setup.go:46`），再做字段校验（用户名 ≤12 位、密码一致、密码 ≥8 位），通过后创建唯一的 Root 超级管理员账号（`controller/setup.go:105`），写入自用/演示模式选项，并落库 `Setup` 记录使站点转入正常态。重复初始化或字段不合规均直接取消，不产生副作用。
