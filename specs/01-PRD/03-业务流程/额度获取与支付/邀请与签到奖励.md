# 邀请与签到奖励

## 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 普通用户 | 用户角色 | 通过邀请码拉新、每日签到、转移邀请额度 |
| 被邀请人 | 用户角色 | 注册时填写邀请码 |
| 网关接入层 | 系统 | 合规前置、签到开关、防重复、额度转移校验 |
| 关系数据库 | 外部系统 | 持久化 user.AffQuota、checkin 记录 |

## 流程描述

本流程聚合三种"非付费"额度获取方式。

**邀请分销奖励**在新用户注册（`model/user.go:617` `finishInsert`）或 OAuth 创建账号（`user.go:676` `FinalizeOAuthUserCreation`）时触发：解析邀请码，若有效且支付合规已确认，向被邀请人即时发放额度（`QuotaForInvitee`），向邀请人累计邀请奖励——但邀请人的奖励先进 `AffQuota`（待提取额度），不直接进可用余额，并累计 `AffCount`/`AffHistoryQuota` 统计。无效邀请码静默忽略，不影响注册。

**邀请额度转移**（`controller/user.go:439` `TransferAffQuota` → `model/user.go:503` `TransferAffQuotaToQuota`）让用户主动将累计的 `AffQuota` 转入可用 `Quota`：需达到最小转移额（`QuotaPerUnit`），事务内行锁校验 `AffQuota` 足够后原子转移。

**每日签到**（`controller/checkin.go:47` `DoCheckin` → `model/checkin.go:55` `UserCheckin`）需签到功能开启（默认关闭），通过 `HasCheckedInToday` 与 `(user_id, checkin_date)` 唯一索引双重防重复，随机发放额度（`MinQuota`~`MaxQuota` 区间），事务内写签到记录并增加额度（SQLite 走无事务分支，额度失败回滚签到记录）。
