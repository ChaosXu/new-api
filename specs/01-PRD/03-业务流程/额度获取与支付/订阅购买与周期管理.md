# 订阅购买与周期管理

## 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 超管/管理员 | 用户角色 | 创建并维护订阅套餐定义 |
| 普通用户 | 用户角色 | 购买订阅（余额或在线支付）获得周期额度 |
| 支付网关 | 外部系统 | 处理订阅外部支付（易支付/Stripe/Creem/Waffo-Pancake） |
| 订阅定时任务 | 系统 | 仅 Master 节点运行，按周期发放/重置额度、处理过期与降级 |
| 关系数据库 | 外部系统 | 持久化 SubscriptionPlan / SubscriptionOrder / UserSubscription |

## 流程描述

订阅是周期性额度获取机制，涉及套餐定义、购买、生命周期管理三段。

**套餐创建**（`controller/subscription.go:141`）需支付合规前置，校验标题、价格（≤9999）、时长、升降级分组存在性后创建 `SubscriptionPlan`（含各支付渠道产品 ID）。

**购买**支持余额支付与外部支付：
- **余额支付**（`subscription.go:100` → `model.PurchaseSubscriptionWithBalance`）在单事务内行锁用户、校验额度充足、扣额度、创建 `UserSubscription`（含购买上限校验、计算 endTime/next_reset、升级分组）、写 `success` 订单。
- **外部支付**（如 `subscription_payment_epay.go:24`）创建 `pending` 订单后拉起支付，回调时走 `CompleteSubscriptionOrder`（`model/subscription.go:569`）幂等核心：行锁订单 → 校验 `PaymentProvider` 匹配（防跨网关） → 幂等判定（`status==success` 直接返回） → 校验 `pending` → 创建 `UserSubscription` + 同步 TopUp 表 → 标 success。

无论哪种支付，最终都通过 `CreateUserSubscriptionFromPlanTx`（`subscription.go:484`）快照套餐到 `UserSubscription`，并执行用户分组升级（`UpgradeGroup`）。

**生命周期管理**由订阅定时任务（`service/subscription_reset_task.go:29`，仅 Master 节点每分钟运行）驱动：
- **过期**（`ExpireDueSubscriptions`）：`end_time<=now` 的 active 订阅置 expired，并判定分组降级——若用户还有其他 active 升级订阅则保持，否则执行降级。
- **周期重置**（`ResetDueSubscriptions`）：`next_reset_time<=now` 时重置 `AmountUsed=0` 并推进下次重置时间。
- **清理**：7 天前的预扣记录清理。

消费侧（计费时从订阅扣额度）通过 `SubscriptionPreConsumeRecord.requestId` 唯一索引实现幂等，预扣与退款均按 requestId 去重。
