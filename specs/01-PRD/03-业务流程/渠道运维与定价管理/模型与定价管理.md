# 模型与定价管理

## 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 管理员 | 用户角色 | 维护模型元数据、厂商信息、模型部署、同步上游模型 |
| 超管 | 用户角色 | 管理模型倍率与系统 option、同步上游倍率、重置倍率 |
| 上游 new-api 实例 | 外部系统 | 提供倍率与模型列表同步源 |
| 官方倍率源 | 外部系统 | basellm.github.io / models.dev 等公开倍率 |
| 网关接入层 | 系统 | AdminAuth（元数据）/ RootAuth（定价与 option）分层鉴权 |

## 流程描述

模型与定价管理分为两个权限层次：**模型元数据走 AdminAuth**，**定价倍率与系统 option 强制 RootAuth**，体现"管理员可改路由，超管独占定价"的分层。

**模型元数据**（`/api/models/*`、`/api/vendors/*`、`/api/deployments/*`，AdminAuth）：管理员维护模型目录、厂商分类、模型部署，并可 `SyncUpstreamModels` 从上游同步模型列表，写操作留审计。

**定价倍率**（`PUT /api/option/`，RootAuth 独占，`controller/option.go:124` `UpdateOption`）：按 key 做大量前置校验（GroupRatio、ImageRatio、claude、gemini 等）。涉及邀请奖励额度（`QuotaForInviter`/`QuotaForInvitee`）的修改必须先确认支付合规（`option.go:145`）。安全设计：`GetOptions` 自动剥离 Token/Secret/Key 后缀的敏感值，审计仅记录 key 名不记 value。

**同步上游倍率**（`/api/ratio_sync/*`，RootAuth，`controller/ratio_sync.go:142/987`）：`GetSyncableChannels` 选可用上游，`FetchUpstreamRatios` 并发抓取（max 8 并发、10MB 上限）上游 `/api/pricing`，差异比对后可预览或应用，批量校准本地定价。

**重置倍率**（`POST /api/option/rest_model_ratio`，RootAuth，`controller/pricing.go:79`）：倍率调乱时一键回滚默认倍率串并刷新内存，留审计。

**公开倍率配置**（`GET /api/ratio_config`，无鉴权 + CriticalRateLimit）：仅在 `IsExposeRatioEnabled` 时返回倍率配置，供访客定价页评估服务成本。

定价与计费紧密耦合：倍率配置经 `ModelPriceHelper`/`HandleGroupRatio`（`relay/helper/price.go`）在每次调用时参与 quota 计算，含 auto_group 分组倍率与阶梯计费。
