# 全局日志与数据统计

## 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 管理员 | 用户角色 | 查看全局日志/统计/流量趋势、管理充值订单与人工补单 |
| 普通用户 | 用户角色 | 查看自身日志/统计/用量汇总 |
| 第三方客户端 | 外部系统 | 通过只读令牌查询用量汇总（TokenAuthReadOnly） |
| 网关接入层 | 系统 | AdminAuth（全局）/ UserAuth（自身）/ TokenAuthReadOnly（令牌）分层鉴权 |
| 数据库 | 外部系统 | 消费日志、配额数据、充值订单 |

## 流程描述

全局日志与数据统计是平台运营的可观测性底座，按查询者权限分层提供不同视野的数据。

**管理员全局视图**（`/api/log/`、`/api/log/stat`、`/api/data/*`，AdminAuth）：`GetAllLogs`（`controller/log.go:13`）支持多维度过滤（type/时间窗/username/token_name/model/channel/group/requestId）；`GetLogsStat` 提供 RPM/TPM/quota 统计；`GetAllQuotaDates`/`GetAllFlowQuotaDates` 提供全平台配额与流量趋势，用于运营分析与容量规划。

**普通用户自身视图**（`/api/log/self`、`/api/log/self/stat`，UserAuth）：仅返回用户自身的日志与统计，用于追踪用量明细、排查异常、核对计费。

**令牌只读视图**（`/api/log/token`，TokenAuthReadOnly + CORS + CriticalRateLimit，`controller/log.go:74` `GetLogByKey`）：供第三方客户端（如 ChatBox 等）通过只读令牌查询用量汇总，仅校验 key 存在且 token 未禁用，**允许过期/耗尽的令牌查询**（`auth.go:279`），以便客户端显示余额与用量。

**充值订单与人工补单**（`GET /api/user/topup` AdminAuth + `POST /api/user/topup/complete`）：`GetAllTopUps` 列出充值订单核对流水；未到账时 `AdminCompleteTopUp`（`topup.go:495`）走订单级锁与幂等逻辑完成补单（详见"额度获取与支付 - 在线支付充值"），留审计。

**审计日志的存储模型**：`model.RecordOperationAuditLog`（`log.go:229`）写 `Other.op`（前端本地化）、`Other.admin_info`（操作者）、`Other.audit_info`（路由/方法/结果）。普通用户查询时自动剥离 `admin_info` 与 `audit_info`，形成管理操作的可审计闭环，也是本流程"全局日志"的可视化数据源。
