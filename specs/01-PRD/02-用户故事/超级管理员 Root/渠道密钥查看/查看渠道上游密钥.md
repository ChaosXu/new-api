# 查看渠道上游密钥

## 摘要

让超管在多重安全验证保护下查看渠道的上游 API Key 明文，处理最高敏感的密钥管理场景。

## 用例：
- **作为** 超级管理员
- **我想要** 在完成二次安全验证后查看某渠道的上游 API Key 明文
- **以便** 我能在密钥泄露排查、上游迁移或紧急排障时获取完整密钥

## 验收标准：

### 场景：超管通过安全验证查看渠道密钥
- **假设：** 超管已登录（RootAuth）
- **而且假设：** 超管已通过安全验证（2FA 或 Passkey），持有有效的 `X-Security-Proof` 证明（scope=`channel.key.read`）
- **当：** 超管提交 `POST /api/channel/:id/key`（`controller/channel.go` `GetChannelKey`，受 CriticalRateLimit + DisableCache + SecureVerificationRequired）
- **则：** 系统返回该渠道的完整密钥明文，并记录高危审计日志（`channel.key_view`）

### 场景：缺少安全验证被拒绝
- **假设：** 请求未携带安全验证证明，或证明已过期
- **当：** 超管提交查看密钥请求
- **则：** 请求被拒绝（403），返回结构化错误码（`SECURITY_PROOF_REQUIRED` 或 `SECURITY_PROOF_EXPIRED`），需先完成 2FA 或 Passkey 验证

### 场景：安全验证 scope 不匹配被拒绝
- **假设：** 安全证明的 scope 不是 `channel.key.read`，或验证方式不在允许列表（2fa/passkey）内
- **当：** 超管提交查看密钥请求
- **则：** 请求被拒绝（403），返回 scope/method 不匹配的错误码

### 场景：非超管被拒绝
- **假设：** 操作者为管理员（非超管）
- **当：** 管理员尝试查看渠道密钥
- **则：** 请求被 RootAuth 中间件直接拒绝，管理员无权查看渠道密钥
