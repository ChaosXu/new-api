# 确认支付合规

## 摘要

让超管书面确认支付合规声明，解锁邀请奖励、兑换码、订阅等资金流功能。

## 用例：
- **作为** 超级管理员
- **我想要** 确认平台的支付合规声明
- **以便** 我能解锁涉及资金流转的功能（邀请奖励、兑换码、订阅套餐），并留下合规留痕

## 验收标准：

### 场景：超管确认支付合规
- **假设：** 超管已通过 Dashboard 会话登录（非 API access token）
- **当：** 超管提交 `POST /api/option/payment_compliance`（`ConfirmPaymentCompliance`），请求体 `confirmed=true`
- **则：** 系统写入合规记录（确认状态、条款版本、时间、操作者 ID 与 IP），记录 info 日志，返回确认结果

### 场景：使用 API access token 被拒绝
- **假设：** 请求使用了 API access token 而非 Dashboard 会话
- **当：** 超管提交确认请求
- **则：** 请求被拒绝（403），提示该操作需要 Dashboard 会话认证

### 场景：未确认合规被拒绝
- **假设：** 超管未传 `confirmed=true`
- **当：** 超管提交请求
- **则：** 请求被拒绝并提示请确认合规声明
