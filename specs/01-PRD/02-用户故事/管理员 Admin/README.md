# 管理员（Admin）用户故事

> 角色定义：运营与运维人员。继承普通用户全部能力，额外管理用户、渠道、模型、定价、兑换码、订阅计划与全局日志统计。通过 `AdminAuth()` 鉴权（role ≥ 管理员）。

共 20 个用户故事，按用例分组组织。每个故事遵循 Mike Cohn 用例格式 + Gherkin 验收标准。

## 鉴权与权限说明

- **`AdminAuth()`**：管理员（role=10）和超管（role=100）均可访问。
- **渠道 RBAC 双层鉴权**：渠道路由在 AdminAuth 之上叠加 `RequirePermission`。管理员默认拥有 ChannelRead/ChannelOperate/ChannelWrite，但 **ChannelSensitiveWrite（创建/改密钥/删除）默认不授予**，需超管显式授权或由超管执行。
- **角色层级校验**（`canManageTargetRole`）：管理员只能操作比自己角色更低的用户；提升用户为管理员仅超管可用。
- **支付合规前置**：生成兑换码、创建订阅套餐等需超管先确认支付合规。
- 所有管理写操作自动留审计日志。

## 权限边界（管理员不可访问，仅超管 RootAuth）

- 全局系统配置 `/api/option/*`（含支付合规确认、模型倍率重置）
- 自定义 OAuth 提供商 `/api/custom-oauth-provider/*`
- 性能与运维 `/api/performance/*`
- 倍率同步 `/api/ratio_sync/*`
- 系统任务 `/api/system-task/*`、系统实例 `/api/system-info/*`
- 渠道完整密钥查看（`POST /api/channel/:id/key`，RootAuth + 安全验证）
- 提升用户为管理员（`ManageUser` 的 promote）
