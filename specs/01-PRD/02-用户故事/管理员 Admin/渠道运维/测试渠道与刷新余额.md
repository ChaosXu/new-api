# 测试渠道与刷新余额

## 摘要

让管理员主动测试渠道连通性和查询上游余额，保障渠道健康可用。

## 用例：
- **作为** 管理员
- **我想要** 测试单个或全部渠道的连通性，并查询上游余额
- **以便** 我能及时发现并处理故障渠道，掌握渠道余额状况

## 验收标准：

### 场景：管理员测试单个渠道
- **假设：** 管理员已登录（ChannelOperate 权限）
- **当：** 管理员请求 `GET /api/channel/test/:id`（`channel-test.go` `TestChannel`）
- **则：** 系统向该渠道发送测试请求，返回连通性结果（成功/失败及延迟）

### 场景：管理员测试全部渠道
- **假设：** 管理员已登录
- **当：** 管理员请求 `GET /api/channel/test`（`TestAllChannels`）
- **则：** 系统批量测试所有渠道，返回每个渠道的测试结果

### 场景：管理员刷新单个渠道余额
- **假设：** 管理员已登录
- **当：** 管理员请求 `GET /api/channel/update_balance/:id`（`UpdateChannelBalance`）
- **则：** 系统向上游查询并返回该渠道的余额

### 场景：管理员刷新全部渠道余额
- **假设：** 管理员已登录
- **当：** 管理员请求 `GET /api/channel/update_balance`（`UpdateAllChannelsBalance`）
- **则：** 系统批量查询所有渠道余额
