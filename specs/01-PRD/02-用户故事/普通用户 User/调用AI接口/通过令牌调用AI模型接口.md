# 通过令牌调用 AI 模型接口

## 摘要

让普通用户使用自己创建的 API 令牌，通过统一接口调用各类 AI 能力（对话、图像、音频、Embedding 等）。

## 用例：
- **作为** 普通用户
- **我想要** 使用 API 令牌调用对话补全、图像生成、语音转写、Embedding 等多种 AI 接口
- **以便** 我能在自己的应用中集成站点的 AI 能力，统一对接多家上游模型

## 验收标准：

### 场景：用户查看令牌可用模型列表
- **假设：** 用户持有效 API 令牌
- **当：** 用户请求 `GET /v1/models`（`controller.Models`，TokenAuth）
- **则：** 返回该令牌在所属分组下可用的模型列表

### 场景：用户调用对话补全接口
- **假设：** 用户持有效 API 令牌，且令牌余额充足、模型可用
- **当：** 用户请求 `POST /v1/chat/completions`（OpenAI 格式）或 `POST /v1/messages`（Claude 格式）
- **则：** 系统按令牌分组调度上游渠道完成请求，按用量扣减令牌额度并记录日志，返回模型响应

### 场景：用户调用图像生成接口
- **假设：** 用户持有效 API 令牌
- **当：** 用户请求 `POST /v1/images/generations` 或 `/v1/images/edits`
- **则：** 系统按图像计费规则（张数、分辨率等）扣费并返回生成结果

### 场景：用户调用音频接口
- **假设：** 用户持有效 API 令牌
- **当：** 用户请求 `POST /v1/audio/transcriptions`（语音转文字）、`/v1/audio/translations` 或 `/v1/audio/speech`（文字转语音）
- **则：** 系统按时长/字符计费并返回结果

### 场景：用户调用 Embedding 接口
- **假设：** 用户持有效 API 令牌
- **当：** 用户请求 `POST /v1/embeddings`
- **则：** 系统按 token 用量计费并返回向量结果

### 场景：令牌余额不足被拒绝
- **假设：** 令牌剩余额度不足以支付本次请求
- **当：** 用户发起调用
- **则：** 请求被拒绝并提示额度不足
